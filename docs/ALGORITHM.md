# ALGORITHM — 등급 공식

## 한 줄

`score = visit_count_12m × log10(unique_department_count_12m + 1)`

자치구별로 백분위 컷오프하여 등급 부여. 신규는 별도 트랙.

## 왜 이 공식인가

| 차원 | 들어간 이유 |
|---|---|
| **방문 횟수** (`visit_count_12m`) | 단순·직관. "자주 가는 곳"의 일차 시그널. |
| **부서 다양성** (`unique_department_count_12m`) | "총무과 단골" vs "여러 부서 공통 픽" 구분. 광고 시그널과 가장 다른 차별점. |
| **log10 가중** | 부서 수가 1→2→3은 큰 점프, 10→11은 작은 점프 — 한계 효용 체감 반영. |
| **자치구별 백분위** | 강남·도봉 같은 데이터 양 격차를 등급 의미 보존하며 비교 가능하게. |
| **시간 윈도우 12개월** | "지금 가는 곳" 시그널 유지. 24개월 백필은 별도 보관. |

## 정확한 계산

### 1. 점수
```
score = visit_count_12m × log10(unique_department_count_12m + 1)
```

예시:
| 식당 | visit | dept | score |
|---|---|---|---|
| A — 총무과만 8번 | 8 | 1 | 8 × log10(2) ≈ 2.41 |
| B — 5개 부서 1번씩 | 5 | 5 | 5 × log10(6) ≈ 3.89 |
| C — 시장 외 1번씩, 7개 부서 | 7 | 7 | 7 × log10(8) ≈ 6.32 |

→ A < B < C. "부서 다양성이 높을수록 가중", 가설과 일치.

### 2. 백분위 컷오프

자치구별(`places.road_address_part`)로 분포 계산:

```
PARTITION BY road_address_part
ORDER BY score
→ PERCENT_RANK()
```

| 등급 | 조건 |
|---|---|
| **★★★ 강추** | `pct ≥ 0.90` (그 자치구 상위 10%) |
| **★★ 추천** | `0.70 ≤ pct < 0.90` |
| **★ 중립** | `0.40 ≤ pct < 0.70` |
| **(등급 없음)** | `pct < 0.40` — 지도 마커는 옅게, 디테일 패널은 가능 |
| **✦ 신규** | `visit_count_12m ≤ 2` AND `first_visit_at ≥ current_date - interval '3 months'` |

### 3. 신규 트랙

- "방금 등장한 곳"은 점수가 낮아도 시그널 가치 있음.
- 신규 등급은 **점수 기준 등급보다 우선**.
- 누적 3회 이상 되거나 첫 등장 후 3개월 지나면 자동으로 일반 트랙 진입.

## 데이터 분포에 따른 보정

### 초기 데이터 부족 시
- 자치구별 식당 수 < 30이면 백분위가 출렁임 → **전체 서울 분포로 fallback**.
- `place_grade_v1` 머티리얼라이즈드 뷰 안에 fallback 로직 포함.

### 수 6개월 후 안정화
- 절대값 컷오프로 lock 가능 (예: "강추 = score ≥ 5.0").
- 데이터 안정성 모니터링: p90 score의 주간 변동 < 10%면 lock 조건.

## UI 표시 환산

백분위는 사용자에겐 어렵다. UI에선 **백분위 → 절대값**으로 함께 표시:

```
★★★ 강추
이 자치구 상위 10%
방문 12회 · 5개 부서 · 최근 방문 2주 전
```

마커 색상:
- ★★★ 강추: `#ef4444` (빨강) — 가장 강조
- ★★ 추천: `#f59e0b` (주황)
- ★ 중립: `#6b7280` (회색)
- ✦ 신규: `#3b82f6` (파랑)
- 폐업: `opacity: 0.35`

## 폐업 처리

| 조건 | 효과 |
|---|---|
| `place_closure_reports` 누적 ≥ 3 (서로 다른 fingerprint) | `places.is_closed = true`, `closed_at = now()` |
| `is_closed = true` | `place_grade_v1`에서 score 동결 (이전 등급 유지하되 마커 흐림) |
| 신고 1~2건 | 디테일 패널 상단 노란 경고 배너 표시, 등급은 영향 없음 |
| `mark_reopen` 누적 ≥ 2 | `is_closed = false`, `reopened_at = now()` |

## 재계산 정책

- 매일 03:30 KST: `REFRESH MATERIALIZED VIEW CONCURRENTLY place_grade_v1`
- 새 방문 1건 적재 시 즉시 재계산 안 함 (비용 큼). 다음 daily refresh까지 기다림.
- 운영자가 강제 재계산 필요 시 Vercel Cron/API Route `/api/cron/recompute-grades`를 인증 키로 호출.

## 미래 확장 (v1.1+)

### 시간 감쇠 가중치 (검토)
```
score = Σ_i (1 / (1 + age_months_i / 6))    # 6개월 반감기
       × log10(unique_dept + 1)
```
v1엔 단순화 위해 미적용. 데이터 누적되면 A/B 실험.

### 직급 가중치 (검토)
시장단(2.0) · 국장(1.5) · 과장(1.0) · 5급이하(0.7) 가중.
LLM 마스킹 정확도가 검증되면 도입.

### 식당 카테고리 (검토)
"한식·중식·일식·이탈리안·기타" 분류. 카카오 카테고리 직접 사용. 등급과 별도, 필터로만.

### 가격대 시그널 (검토)
`amount / party_size` 평균 → "1인당 평균" 표시. 등급 공식엔 미반영.

## 평가 지표

| 지표 | 목표 | 측정 |
|---|---|---|
| 등급 분포 균형 | ★★★ 10±2%, ★★ 20±5%, ★ 30±5% | 자치구별 |
| 등급 안정성 | 주간 등급 변동 < 5% | 같은 식당의 등급이 일주일 새 자주 바뀌면 신뢰도↓ |
| 신규→일반 전환률 | 신규 식당 중 60일 후 ★ 이상 도달 ≥ 30% | "신규" 라벨이 의미 있는지 |
| 폐업 자동탐지 정확도 | 신고 3건 자동 폐업 후, 운영자 사후 검토 정답률 ≥ 90% | 샘플링 |
