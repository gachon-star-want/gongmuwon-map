# 01. 레퍼런스 분석

## 목적

거지맵 캡처를 공무원맵 리터치에 맞게 해석하고, 가져올 UI 패턴과 가져오지 않을 패턴을 명확히 구분한다.

## 읽는 대상

- UI/UX 설계자
- 프론트엔드 구현자
- 시각 QA 담당자

## 완료 기준

- 레퍼런스를 그대로 복제하지 않고 공무원맵의 공공데이터 서비스 목적에 맞게 변환한다.
- 레퍼런스의 광고·커뮤니티·댓글·평점·후기·게임화 요소를 그대로 복제하지 않는다. 광고 수익화는 허용하되 공무원맵의 지도 탐색과 출처 확인을 방해하지 않는 별도 UX로 설계한다.
- 지도 우선 경험과 모바일 bottom navigation 패턴만 선별적으로 가져온다.

## 레퍼런스 핵심 인상

거지맵은 화면 중심이 명확하다. 지도 화면에서는 지도가 배경이 아니라 작업 표면이고, 검색·리스트·액션은 지도 위에 얹힌 floating layer로 존재한다. 공무원맵도 첫 화면에서 데이터 테이블보다 지도 탐색을 먼저 느끼게 해야 한다.

다만 거지맵의 목적은 커뮤니티와 광고 수익화에 가깝다. 공무원맵은 법령상 공개 데이터의 재가공 서비스이므로, 커뮤니티 신뢰 신호를 그대로 가져오면 법적 리스크와 제품 정체성 혼선이 생긴다. 광고 수익화 자체는 가능하지만, 지도 조작·원문 확인·공공누리 출처 표시보다 우선해서는 안 된다.

## 가져올 패턴

### 1. 지도 우선 화면

- 지도는 full-bleed로 깔고, 패널은 지도 위 floating layer로 배치한다.
- 지도 이동·확대·마커 선택이 첫 번째 상호작용이어야 한다.
- 화면 가장자리 여백은 패널 안전 영역으로만 쓰고, 지도 영역을 임의 카드 안에 가두지 않는다.

### 2. 가벼운 floating control

- 검색창, 필터 chip, 정렬 control은 상단 floating bar로 묶는다.
- 컨트롤은 흰색/반투명 배경, 8px 이하 radius, 얕은 shadow를 사용한다.
- 컨트롤은 지도 조작을 방해하지 않도록 필요한 순간에만 확장한다.

### 3. 밀도 높은 리스트

- 리스트 row는 한눈에 이름, 지역, 등급, 방문 수, 최근 방문일을 비교할 수 있어야 한다.
- desktop에서는 리스트를 지도 위 보조 sheet로 열 수 있다.
- mobile에서는 bottom sheet의 list tab에서 리스트를 제공한다.

### 4. 모바일 bottom navigation

- 모바일에서는 주요 모드를 하단에 둔다: 지도, 목록, 필터, 정보.
- 엄지 조작에 맞춰 bottom nav와 bottom sheet를 우선한다.
- sheet는 peek, mid, full 상태를 가져야 한다.

### 5. compact badge와 chip

- 등급, 자치구, 폐업 제보, 신규 등 상태는 짧은 badge/chip으로 표시한다.
- chip은 필터 상태를 빠르게 읽고 해제할 수 있어야 한다.

## 그대로 가져오지 않을 패턴

### 1. 침습적 광고 영역

- 좌우 대형 banner, 지도 하단 고정 banner, 리스트 옆 과밀 광고 슬롯은 그대로 복제하지 않는다.
- 광고를 도입하더라도 "광고" 또는 "후원" 라벨을 표시하고, source pill·지도 컨트롤·신고 CTA·원문 링크를 가리지 않는다.
- 기본 구현은 광고 설정값이 없으면 빈 공간을 만들지 않는 ad-ready 구조가 적합하다.

### 2. 커뮤니티 기능

- 게시글, 댓글, 답글, 좋아요, 비추천, 투표, 레벨, 사용자 랭킹은 이번 지도 리터치 PR 범위가 아니다.
- 운영자가 커뮤니티·댓글·평점·후기를 도입하기로 결정하면 `docs/LEGAL_PRIVACY.md`, `docs/RISK_MITIGATION.md`, ADR을 먼저 갱신하고 모더레이션·신고·게시중단 정책을 함께 설계한다.

### 3. 게임화된 신고·심판 UI

- "심판하기", "제보하기"처럼 사용자 참여를 경쟁적으로 유도하는 표현은 쓰지 않는다.
- 신고 CTA는 조용한 icon+text button으로 제공한다.
- 신고는 폐업 신고와 정보 수정·삭제 요청으로만 제한한다.

### 4. 강한 공지 모달

- 첫 진입 공지 모달은 지도 탐색을 막으므로 도입하지 않는다.
- 법적 안내는 source pill, 정적 문서, detail drawer의 원문 링크로 분산한다.

### 5. 음식점 평가처럼 보이는 표현

- "맛집", "인기", "검증됨", "추천 후기" 같은 표현은 현재 공공데이터 등급과 혼동되므로 이번 지도 리터치에서는 쓰지 않는다.
- 등급은 "방문 빈도 + 부서 다양성" 시그널임을 유지한다.

## 공무원맵으로 변환하는 기준

| 레퍼런스 패턴 | 공무원맵 변환 |
|---|---|
| 지도 위 다수 floating panel | search/filter, list sheet, right drawer, source pill로 제한 |
| 커뮤니티 랭킹 | 자치구별 공공데이터 기반 식당 목록 정렬 |
| 사용자 제보 | 폐업 신고, 정보 수정·삭제 요청만 |
| 댓글·후기 | 이번 리터치 범위 밖. 도입 시 ADR·법무·모더레이션 설계 선행 |
| 광고 banner | 침습적 배치는 복제하지 않음. 광고 수익화는 별도 ad-ready layer로 설계 |
| 모바일 bottom nav | 지도·목록·필터·정보 전환으로 사용 |
| 카테고리 chip | 자치구, 등급, 정렬 chip으로 사용 |

## 현재 공무원맵에 대한 시사점

- 현재 홈은 control panel, map, detail panel의 3열 grid라 지도가 보조 영역처럼 보인다.
- 첫 데이터 로드 후 첫 번째 식당을 자동 선택해 사용자가 의도하지 않은 detail state로 진입한다.
- 홈 footer가 74px 높이를 차지해 지도와 모바일 sheet의 공간을 줄인다.
- Kakao SDK는 `libraries=clusterer`를 로드하지만 마커 클러스터링을 실제 사용하지 않는다.
- 지도 instance와 overlay를 effect마다 재생성하는 구조라 마커 수가 늘면 성능과 상태 안정성이 떨어진다.

## 결론

이번 리터치는 거지맵의 "지도 위에 필요한 UI를 얹는 방식"을 참고한다. 공무원맵은 우선 공공데이터 지도 서비스이므로 출처 확인, 지역 탐색, 등급 비교, 법적 안전을 훼손하지 않는 선에서 수익화 layer를 열어둔다.
