# 02. 제품 요구사항

## 목적

UI/UX 리터치의 제품 목표, 기능 범위, 법적 제약, 비목표를 구현 전에 확정한다.

## 읽는 대상

- 제품 책임자
- 프론트엔드 구현자
- API 구현자
- QA 담당자

## 완료 기준

- 홈 화면이 full-bleed map 중심으로 재구성된다.
- 데스크탑과 모바일 모두 같은 데이터·상태 모델을 공유하되, 화면 구조는 각 기기에 맞게 최적화된다.
- 광고 수익화는 허용하되, 이번 리터치에서는 지도 조작과 상세 확인을 방해하지 않는 ad-ready 구조로만 다룬다.
- 댓글·평점·후기·커뮤니티는 이번 리터치 PR 범위 밖이다. 도입하려면 ADR, 법무 문서, 모더레이션 정책을 먼저 갱신한다.

## 배경

공무원맵의 핵심 가설은 "공무원이 여러 부서에서 반복 방문한 식당은 광고가 아닌 실사용 시그널"이라는 것이다. 따라서 홈 화면은 설명 페이지나 목록 서비스가 아니라, 사용자가 서울 지도에서 지역과 등급을 좁혀가며 식당을 발견하는 탐색 도구여야 한다.

## 리터치 목표

1. 지도 우선 UX로 전환한다.
2. 마커가 많은 서울 전체 화면에서 클러스터 기반 탐색을 제공한다.
3. 검색·필터·선택 상태를 URL query와 동기화해 공유와 복귀가 가능하게 한다.
4. 모바일에서는 bottom nav와 bottom sheet로 한 손 조작을 지원한다.
5. 법적 안전선과 출처 표시를 홈 화면에서도 유지한다.

## 핵심 사용자 시나리오

### 지역 직장인

- 서울 강남구를 선택한다.
- 등급 `★★★`, `★★`만 켠다.
- 지도에서 가까운 클러스터를 확대한다.
- 식당 marker를 선택해 방문 횟수, 부서 수, 최근 방문일, 원문 링크를 확인한다.

### 출장·관광객

- 검색창에 자치구 또는 식당명을 입력한다.
- 결과 목록에서 식당을 고른다.
- 카카오맵에서 보기 버튼으로 길찾기 전환을 한다.

### 시민 감시·기자

- 특정 자치구의 상위 방문 식당을 정렬한다.
- 상세 drawer에서 방문 기록과 원문 링크를 확인한다.
- 데이터를 인용할 때 공공누리 출처와 원문을 확인한다.

## 기능 요구사항

| 우선순위 | 요구사항 |
|---|---|
| P0 | 홈은 full-bleed map으로 시작한다. |
| P0 | 초기 진입 시 `selectedPlace`를 자동 선택하지 않는다. |
| P0 | 낮은 줌에서는 클러스터를 표시하고, 확대하면 개별 마커를 표시한다. |
| P0 | 등급, 자치구, 검색어, 정렬, 선택 식당을 URL query와 동기화한다. |
| P0 | 데스크탑은 floating search/filter와 right drawer를 사용한다. |
| P0 | 모바일은 bottom nav와 bottom sheet를 사용한다. |
| P0 | 홈 footer는 source pill로 축소한다. |
| P0 | 정적 문서 페이지 footer는 기존처럼 상세 출처와 운영자 정보를 유지한다. |
| P0 | `/api/v1/places`는 breaking change 없이 유지한다. |
| P0 | 신규 UI 전용 API로 `/api/v1/places/search`, `/api/v1/regions`를 추가한다. |
| P1 | 목록 sheet에서 정렬을 제공한다: 추천순, 최근 방문순, 방문 많은순. |
| P1 | marker 선택 후 detail drawer/sheet에서 원문 링크와 신고 CTA를 제공한다. |
| P1 | 날짜는 `YYYY.MM.DD`로 표시한다. |
| P1 | 모든 CTA는 lucide icon 또는 icon+text button으로 통일한다. |
| P1 | 광고 수익화를 위한 optional `AdSlot` 위치를 정의하되, 설정값이 없으면 렌더링하지 않는다. |

## 데이터 표시 요구사항

- 식당명, 주소, 자치구, 등급, 방문 횟수, 부서 수, 최근 방문일, 평균 인당 금액을 표시한다.
- 평균 인당 금액이 없으면 빈 값을 억지로 표시하지 않는다.
- 원문 링크는 방문 기록 row마다 제공한다.
- 선거직 고위공무원 외 개인 실명은 적재 단계에서 이미 마스킹되어 있어야 한다.
- 표시 단계에서 평문 실명을 숨기는 방식은 금지한다.

## 법적·운영 제약

- 댓글·평점·후기·커뮤니티는 현행 법무 문서와 충돌하므로 이번 리터치 PR에 포함하지 않는다. 운영자가 도입 의사를 확정하면 ADR과 `LEGAL_PRIVACY.md`, `RISK_MITIGATION.md`를 갱신한 뒤 별도 구현한다.
- 공무원 비위, 부정행위, 낭비를 단정하거나 암시하는 문구를 쓰지 않는다.
- 등급은 식당의 맛이나 품질 평가가 아니라 방문 빈도와 부서 다양성 기반 통계 신호로 표현한다.
- 공공누리 제1유형 출처 표시는 홈 source pill, 정적 문서 footer, OpenAPI, `llms.txt`에 유지한다.
- 정보 수정·삭제 요청은 접수 즉시 임시 hide되는 운영 정책을 UI에서 약화하지 않는다.
- 폐업 신고는 익명 중복 방지 fingerprint 정책을 유지한다.
- 광고는 공공데이터 출처, 등급, 원문 링크와 혼동되지 않게 "광고" 또는 "후원" 라벨을 표시한다.

## 이번 리터치 PR의 비범위

- 사용자 계정, 프로필, 레벨, 활동 랭킹
- 댓글, 평점, 후기, 좋아요
- 음식 카테고리 자동 평가
- 원문 데이터 정책 변경
- 등급 산식 변경
- `/api/v1/places` 기존 응답의 breaking change
- 실제 광고 네트워크 연동. 단, ad-ready slot과 환경변수 기반 숨김 구조는 허용한다.

## 성능 요구사항

- 지도 instance는 최초 1회 생성 후 유지한다.
- marker와 clusterer instance는 `useRef`로 관리한다.
- 필터 변경 시 지도 전체를 재생성하지 않는다.
- 500개 marker 기준으로 desktop interaction이 끊기지 않아야 한다.
- 검색 입력은 debounce를 적용한다.
- 모바일 LCP 목표는 기존 PRD 기준과 동일하게 2.5초 미만을 목표로 한다.

## 접근성 요구사항

- 모든 버튼과 marker에는 접근 가능한 이름을 둔다.
- 키보드로 검색, 필터, 목록, 상세 drawer, 신고 모달에 접근 가능해야 한다.
- marker는 `aria-label`에 등급, 식당명, 자치구를 포함한다.
- 모달은 focus trap을 유지한다.
- `prefers-reduced-motion` 사용자는 drawer/sheet 애니메이션을 줄인다.

## 제품 승인 기준

- 첫 화면에서 지도가 화면 대부분을 차지한다.
- 아무 query 없이 `/`에 들어오면 선택된 식당이 없다.
- `?place={id}`가 있을 때만 해당 식당이 선택된 상태로 열린다.
- `q`, `region`, `grade`, `sort`, `place` query가 새로고침과 뒤로가기에 반영된다.
- home source pill과 정적 문서 footer 모두 공공누리 출처를 표시한다.
