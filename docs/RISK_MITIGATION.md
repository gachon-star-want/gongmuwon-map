# RISK_MITIGATION — 민원·가처분·운영 리스크 플레이북

## 핵심 인식

법적으론 합법(=`LEGAL_PRIVACY.md`)이지만 **운영 리스크는 별개 차원**이다. 다음 시나리오는 모두 v1에서 발생 가능:

1. 공무원 개인이 "내 직급·부서 노출 빼라" 항의
2. 자치단체(시청·구청·의회 사무처)가 "우리 데이터로 이런 거 만들지 말라" 항의
3. 식당 사장이 "우리 식당 빼라" 항의
4. **법원 가처분** (서비스 중단·게시중단) — 가장 위협적
5. 방송통신심의위 권리침해 신고
6. 개인정보위 신고
7. 언론 부정적 기사화

## 4겹 방어막

### 1겹: 노티스앤테이크다운 (Notice-and-Takedown)
정통망법 44조의2 절차 준수 + 그 이상.

| 단계 | 시간 | 행동 |
|---|---|---|
| **즉시 (0초)** | 요청 접수 즉시 | 해당 식당/방문 row의 `hidden_at = now()` 자동 설정 |
| **5초** | 접수 확인 | "접수되었습니다. 72시간 내 검토 후 회신드립니다." 이메일·화면 표시 |
| **0~72h** | 운영자 검토 | 합당 사유 판단 |
| **72h 이내** | 결정 | (a) 영구 삭제 / (b) 부분 마스킹 강화 / (c) 복원 + 사유 회신 |

복원 시에도 신청인이 이의 제기 가능 → 30일간 분쟁조정.

### 2겹: 표기 정책 (선거직 외 마스킹)
[LEGAL_PRIVACY.md](LEGAL_PRIVACY.md#우리-표기-정책)와 동일. **개인 식별성을 최소화**.

추가: **준식별성 보호 토글**
- 사용자가 더 강한 추상화 원하면 `?abstraction=high` 쿼리로 부서명→"본청"/"의회" 수준으로.
- 디폴트는 일반 모드.

### 3겹: 운영자 신원 노출 + 가처분 대응
- 정통망법상 운영자 정보 노출 의무.
- 가처분 송달 받을 수 있는 주소 명시.
- 가처분 송달 시 24시간 내 대응 매뉴얼(아래) 발동.

### 4겹: 면책 조항 + 약관
[LEGAL_PRIVACY.md](LEGAL_PRIVACY.md#면책-조항-disclaimer)와 동일.

## 시나리오별 대응 플레이북

### 시나리오 A — 공무원 개인의 "내 정보 빼라"

| 단계 | 행동 |
|---|---|
| 접수 채널 | 운영자 이메일 또는 "정보 수정·삭제 요청" 폼 |
| 자동 처리 | 폼 접수 시 즉시 hide |
| 검토 | 신청인의 본인 식별 여부 확인 (이메일 도메인이 기관 도메인이면 신뢰도↑) |
| 결정 | 5급 이하: 즉시 영구 마스킹 강화 / 임명직: 직급+부서로 더 추상화 / 선거직: 원칙적으로 거부 (단 본인의 동석 사실이 부정확하다는 주장 시 별개 검토) |
| 회신 | 72h 내 결정 사유 이메일 |

### 시나리오 B — 자치단체의 항의

| 단계 | 행동 |
|---|---|
| 접수 채널 | 공문 또는 운영자 이메일 |
| 즉시 조치 | 해당 기관 데이터의 임시 hide 가능하지만, 원본이 법령상 공개라 거부 정당 |
| 회신 | "본 서비스는 공공누리 제1유형 데이터를 가공·재공개하며, 법령상 의무 공개된 정보입니다. 출처는 푸터에 명시되어 있습니다. 특정 식당·방문 row의 정보가 부정확하다면 [정정 요청]을 보내주세요." |
| 협조 | 데이터 정확성 향상이라면 적극 협조. 단 데이터 자체 차단·삭제 요구는 거부. |

### 시나리오 C — 식당 사장 "우리 식당 빼라"

| 단계 | 행동 |
|---|---|
| 접수 | "정보 수정·삭제 요청" 폼 |
| 자동 처리 | 즉시 hide |
| 결정 | (a) 폐업이면 영구 hide / (b) 영업 중인데 "공무원 단골" 라벨이 영업 방해라 주장 → 케이스 바이 케이스. 우리는 "방문 빈도" 사실만 표시할 뿐 평가 안 함을 안내. |
| 옵션 | "식당이 직접 본 서비스에 정정·동의 표시"를 제공할 수 있는 v2 기능 검토 |

### 시나리오 D — 법원 가처분 송달 (최우선)

| 단계 | 행동 | SLA |
|---|---|---|
| 접수 | 송달지 주소(`경기도 성남시 분당구 수내로 39`)로 송달 또는 이메일 통지 | — |
| 즉시 | 운영자에게 푸시 알림 (Resend), Slack/카카오톡 미러링 | 1h |
| 1차 조치 | 가처분 신청 대상 식당·방문 row 즉시 hide | 6h |
| 변호사 자문 | 가처분 신청 사유 검토, 응답서 준비 | 24~48h |
| 응답 | 변호사 통해 답변서 제출 또는 자진 합의 | 48~72h |
| 데이터 백업 | 가처분 인용 시 영구 삭제 필요할 수 있음 → 백업은 별도 저장소 보관 (외부 클라우드) | — |

### 시나리오 E — 방심위 권리침해 신고

| 단계 | 행동 |
|---|---|
| 접수 | 방심위 통지 | 
| 즉시 | 정통망법 44조의2에 따라 30일 임시조치 (hide) |
| 결정 | 방심위 결정 또는 분쟁조정위 결과에 따름 |
| 학습 | 같은 유형 반복 신고 시 데이터 표기 정책 재검토 |

### 시나리오 F — 개인정보위 신고

| 단계 | 행동 |
|---|---|

| 협조 | 적극 협조, 데이터 가공·마스킹 정책 문서 제출 (`LEGAL_PRIVACY.md`, `PIPELINE.md`) |
| 시정명령 시 | 시정 후 명문화 |

### 시나리오 G — 언론 부정적 기사

|---|---|

| 학습 | 정당한 비판이면 정책 보완. 부당한 공격이면 무대응. |

## 모더레이션 도구 (v1.1)

v1엔 자동 룰 + 수동 처리. v1.1에 운영자 대시보드:
- 신규 신고 큐
- 자동 hide된 row 일괄 검토
- 마스킹 강도 토글
- 데이터 분포 시각화

## 비용 예상

| 항목 | 1회 비용 |
|---|---|
| 가처분 대응 변호사 자문 | 50~200만 원 |
| 변론·답변서 | 100~500만 원 |
| 본안 소송 (드뭄) | 수백~수천만 원 |

→ **법무 비상금** 100만 원 사전 적립 권장. AdSense·후원 도입 시 우선 적립.

## 데이터 백업 정책

- Supabase 자동 백업 (Pro plan, 매일 7일 보관).
- 별도: 주 1회 `pg_dump` → 개인 GitHub repo 또는 Google Drive (암호화).
- 가처분 영구삭제 후 백업까지 폐기되는지 신청인이 확인하는 경우는 드물지만, 정책상 명시.

## 사용자 신뢰 신호

- 푸터·About 페이지에 **"이 서비스는 공공누리 제1유형 데이터를 사용합니다"** 명시
- 모든 식당 카드에 원문 PDF 링크 → "출처 확인 가능" 시그널
- 운영자 실명·이메일·연락처 노출 → "도망가지 않는 운영자"

## 무엇을 안 할 것 (No-Go)

- ❌ 부정행위·비위 의심 라벨링
- ❌ 공무원 개인의 식습관·취향 추론
- ❌ 가격대로 "고급/저급" 평가
- ❌ 사용자 익명 댓글
- ❌ 익명·운영자 미공개 (= 가처분 송달 불가능 상황 회피 시도)
- ❌ "광고가 아니다, 진짜 맛집이다"식 마케팅 표현
